# V2.3 RC2 修正與驗收

修正 PDF 直接以 data URL 下載在手機可能無反應的開啟方式，改成使用者點擊時同步開啟 PDF Blob 預覽。拒絕非 PDF 附件並顯示訊息；彈出視窗被阻擋時提供提示。這不會修復已損壞或原先未存入的附件。

本機資料庫交易前檢查連線。若為已關閉的連線，重新開啟相同資料庫；不刪除資料、不重播已開始的寫入交易。還原保留 policies 與 settings 同一原子交易，失敗訊息留在備份區。快取升級 shell-4。

## 自動驗證

- `npm test`：16/16 通過，涵蓋既有行事曆與 Excel 規則、連線重開、PDF 預覽、無效附件及彈出阻擋。
- `NODE_PATH=/tmp/renewal-rc2/node_modules node tests/restore-recovery.cjs`（需安裝 fake-indexeddb）：模擬在選檔與寫入之前連線關閉，還原仍保留 PDF；設定寫入失敗時整批回滾，原保單不變。
- 以上為模擬測試，不等同 iPhone Safari 實機通過。

## 使用者需驗證

1. 使用原本 V2.3 入口重新整理，確認頁首 RC2；必要時關閉重開再整理，不清除網站資料。
2. 在既有保單按「開啟 PDF」，確認能預覽；如顯示附件格式錯誤，保留原始備份及 PDF，回報訊息。
3. 關閉頁面再開，確認保單仍在，再測備份／還原及附加 PDF。
4. Google 實際新增、修改、取消已由使用者回報通過；RC2 尚需回歸驗證，iPhone 實際通知送達尚未驗收。

原 V2.2 正式版未修改。手動 iCloud JSON 備份方式維持，沒有新增背景同步。

- 使用者已回報 RC2 在 iPhone 可開啟 PDF；關閉後同一入口重開，保單與 PDF 可讀取。

### RC2 線上同步回歸（使用測試資料）

1. 先下載 JSON 備份。開啟 RC2，連接 Google。
2. 新增唯一測試保單：被保險人「RC2日曆測試」、保單號碼「RC2-CAL-TEST」、到期日 2026-12-10、狀態待續保。確認專用日曆 2026-11-10 出現一筆「產險續保提醒」，同步失敗 0 筆。
3. 再按兩次重新同步，確認該測試事件仍僅一筆。
4. 改到期日 2026-12-11，確認事件移至 2026-11-11，舊日期沒有殘留測試事件。勿混淆同日正式保單的同名事件。

### iPhone 通知送達（暫改測試事件，不改正式資料）

1. 在 iPhone Google 日曆 App 登入同一 Google 帳戶，顯示專用日曆，確認可見上述測試事件。iPhone 設定中的 Google 日曆通知需允許，並檢查專注模式與通知摘要。
2. 暫時關閉續保系統頁面。在 Google 日曆只編輯上一步測試事件，取消全天，改為現在起至少 10 分鐘後，通知設活動開始時。這是加速通知測試，並非正式提醒規格變更。
3. 儲存後鎖屏，等待並記錄通知實際到達時間／是否有鎖屏提示。測試期間不要重開續保系統或按同步，以免測試時間被正式同步規則還原。
4. 收到通知後，回續保系統重新授權並同步，確認該測試事件恢復為 2026-11-11 全天；將測試保單設為不續保，確認測試事件移除。
5. 若未收到，先保留測試結果與設定畫面，不能將通知標示通過。若 Google 日曆未安裝或使用 Apple 行事曆，先確認實際接收端，再給相應步驟。
