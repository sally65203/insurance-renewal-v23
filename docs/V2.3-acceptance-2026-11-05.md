## 使用限制
1. 應固定使用經核對的 V2.3 主畫面圖示。Safari、對話內瀏覽器、舊 V2.2 圖示不能視為同一份本機資料；多入口同時使用可能產生不同資料版本。
2. Google token 僅留記憶體，重新開啟或到期可能需再次按連接 Google。兩個 ID 應在同一環境保存，清除網站資料會影響設定。
3. 關閉系統不背景同步新異動；已送到行事曆的事件由行事曆處理通知，受裝置帳戶、權限、同步及專注模式等條件影響。
4. 備份仍為 iCloud Drive 手動 JSON，包含附件及映射，不含 Google token，不是 iCloud 自動同步。
5. 本機資料並無伺服器副本；清除網站資料或刪除 App 前必須先備份。CSV 不包含 PDF，不能代替 JSON 還原。
6. 同一專用日曆暫以單一固定入口管理，不將多裝置各自修改資料宣稱為雙向雲端同步。

## 正式版發布前最少操作
- 在新的「續保 V2.3」主畫面圖示核對完整保單總數、抽查 PDF，關閉重開再核對；如未通過先保留備份，不清除資料。
- 用測試保單驗證原全天提醒實際通知時間。若目前全天事件於凌晨提醒不符合日常需求，應先確認既定提醒時間再修改及驗證，不直接宣稱正式提醒時刻驗收完成。
- 上述確認後才更新正式標籤與發布紀錄；不要求重做已通過的指定時間通知、取消、PDF 測試。

## 每年續保操作（現有功能範圍）
- 系統不自動將舊保單延長一年，也不從日曆取得下一年度保單。
- 每年使用保險公司當年度 Excel 清冊批次匯入，再核對公司、險種、續保單號及起迄日；相同車號的不同險種分別保留。
- 新增新年度保單不會自動將上一年度保單結清。續保完成後，需將舊保單標為已續保，並確認新保單處於正確狀態與日期。
- 去重身分包含公司、險種、保單號碼。如果新年度沿用完全相同身分，重匯可能略過而不覆蓋，應查看略過原因並人工核對／修改；目前沒有依年度自動建立歷史版本功能。
- 不應將舊保單只改到期日就視為實際續保完成；操作時以保險公司文件為準。異動完成後同步並手動備份。
